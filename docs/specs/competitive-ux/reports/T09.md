## Deviations / notes
Both capture paths are installed. `DeckLabBuilder.command` is wrapped so extension callers are recorded from the deck state before that queued command runs, with generated card and zone ids filled from the saved document. Builder-internal `command()` calls (row +/−) are recorded by diffing entries and zones between renders. Undo and redo call the unwrapped command, so they are not recorded as new edits. A 409 is recognized from the builder's save-state title ("A newer version was loaded. Reapply your last change.") and clears both stacks.

`deck-lab-builder.js` was not edited. Shift+Enter is a capture-phase listener on `[data-card-search]` that stops the builder's Enter handler and activates the first `[role=option]`.

Inverses cover add card, remove entry, set quantity, adjust quantity, move entry, set role, rename zone, create zone, and delete zone (recreate the zone, then move its entries back). Any other kind clears the redo stack and sets the save-state title to `Can't undo <action>`. Tooltips name the action that undo/redo will reverse, for example `Undo: remove Sol Ring`. Re-adding a removed card uses `add_card`, so the new row gets a new entry id; AC-1 compares card, quantity, zone, role, commander flag, and zone id/name.

The card image dialog now follows the new script `{% endif %}` inside the scripts block. It is still outside `{% if not shared %}`, so shared decks keep it, and the existing markup test still sees it after the last `{% endif %}`.
