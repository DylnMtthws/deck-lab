## Deviations / notes

- The spec required the API to be defined "after the first `render()` call near the end of the file." The `onRender` listener infrastructure (`_onRenderListeners`, `_runOnRenderListeners`, `_entryMatches`) is defined earlier (near the `render()` function definition), so the patched `render` is active before the first render call. The `window.DeckLabBuilder` object and event dispatchers are defined at the end of the IIFE as specified.
- `document.dispatchEvent` calls are guarded through `_dispatchBuilderEvent()` to avoid breaking existing harnesses that use a minimal document mock without `dispatchEvent`. The guard checks `typeof document.dispatchEvent === "function"` before calling.
- The `_dispatchBuilderEvent` helper wraps `dispatchEvent` in a try/catch since the `CustomEvent` constructor may not exist in some test harnesses.
- The entry filter chip uses a child `<span>` for the label text and a child `<button>` for the clear action, because the fake DOM's `textContent` getter returns only child text when children exist (ignoring the parent's `_text`).
- The `entryfilter` scenario had to query `[data-entry-id]` through `document.getElementById("table-view").querySelectorAll(...)` instead of `#table-view [data-entry-id]` because the fake DOM's CSS selector parser doesn't support descendant combinators.
- Event bubbling was added to the harness's `Element.dispatchEvent` to support the delegated hover listener on `#table-view`.
- The `command` member returns the promise from the internal `command()` unchanged. For shared-mode, `command()` returns `Promise.resolve()` without calling fetch. The test builds a separate DOM with `data-shared="true"` to verify this.
- The spec says the API exposes `shared` as a boolean. It's implemented as a getter (`get shared() { return shared; }`) so it always reflects the current value.
- Amendment 1: Selection event now fires from a single point in `syncSelection()` comparing `_lastSelectionSnapshot` with current `selectedEntries`. This covers checkbox clicks, clear-selection button, bulk move, group select-all, playmat card click, and playmat selection bar clear — without scattering dispatch calls. The `setSelection` method no longer dispatches directly; `syncSelection` handles it.
- `setEntryFilter` chip label: when no label is provided, chip text is exactly `Filtered`. With a label, it's `Filtered: <label>`. Fix uses `_entryFilterLabel ? "Filtered: " + _entryFilterLabel : "Filtered"`.
- `focusEntry` and `railSection` coerce `id` with `String(id)` at the top of each function to prevent non-string id arguments from throwing.
- The `_lastSelectionSnapshot` variable stores the sorted, comma-joined set of selected entry ids. On each `syncSelection()` call, if the snapshot differs, `deck-lab:selection` fires and the snapshot is updated. This ensures no double-fire from `setSelection` (which calls `syncSelection` once) and no fire when the selection is unchanged.
