## Deviations / notes

- `or` is treated as unsupported (it is a Scryfall boolean operator). When two
  type terms appear on either side of `or`, the last-parsed type wins in the
  filter output, which is indistinguishable from the first type until `or`
  is supported. The unsupported notice informs the user.
- The tokenizer coalesces `prefix:"quoted value"` patterns where the prefix
  immediately touches the opening quote (e.g. `o:"draw a card"`). Standalone
  quoted strings (e.g. `"Sol Ring"`) are unquoted to bare words.
- `test_plain_query_matches_unparsed` compares result counts rather than full
  HTML to avoid false diffs from random CSP nonces.
