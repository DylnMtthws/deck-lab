## 1. Shared event contract v1

### Identity and compatibility

Domain state remains authoritative. This adds a durable, bounded public event journal in the existing SQLite database; it is not a new execution system or budget authority. Existing turn_id is run_id; keep existing generation and deck revision. Every read and mutation authenticates current owner and deck access server-side. Never trust client owner identifiers or permit source IDs to bypass authorization. Cross-owner IDs return no data.

Each submission has client_request_id, deduplicated within owner using the existing fingerprint (deck, revision, request, mode and constraints). Same ID/same fingerprint returns the original run without readmission or another charge; changed fingerprint is a conflict. Steering also carries client_request_id, retaining its existing owner/deck/request scope and body fingerprint: same-ID replay returns the CURRENT projection of the original replacement without restarting again; changed body is a conflict. Resolve deduplication before checking expected current-run fields, so a retry of a successfully replaced origin is recognized. Reconnect and status refresh cannot submit or admit a new paid turn. Existing GET-triggered dispatch/recovery may start already-admitted work and terminalize orphaned jobs; these maintenance effects are journaled. A deliberate retry after a known terminal outcome uses a NEW request ID and may incur cost. Retrying an uncertain submission uses the ORIGINAL ID. Do not promise provider exactly-once execution.

Public projection top-level fields:

```
contract_version: "assistant.events.v1"
server_time: UTC RFC3339 timestamp
run: {
  run_id, client_request_id, generation, deck_revision,
  accepted_at?, worker_started_at?, ended_at?,
  budget_group_id?, budget_started_at?, deadline_at?,
  steered_from_run_id?, superseded_by_run_id?,
  lifecycle: queued | running | completed | stopped | failed | interrupted | superseded,
  evidence_status: not_started | partial | reviewed | unavailable,
  fulfillment: unknown | complete | partial,
  obligations: [], missing_obligations: [], legacy_fulfillment?,
  stop_requested_at?, error?: {code, message, retryable},
  last_sequence: integer
}
operational: {background_work_pending?, cost_pending?, provider_outcome_unknown?, observed_at}
mode: snapshot | delta | reset_required
snapshot_page?: {token, page_index, page_count, through_sequence, entities}
events?: [event envelope]
cursor: {after_sequence?, through_sequence, last_sequence, has_more, reset_reason?}
```

RFC3339 timestamps are normalized from existing epoch fields. Nullable fields are explicit. Evidence status is server-derived aggregate review coverage, never a certificate that every statement is true. Completed means execution ended with an answer; it does not imply complete fulfillment or reviewed evidence. Failed/interrupted may retain partial findings. Superseded is terminal for publishing into the current run. queued includes admission wait; running begins at worker claim, not at a decorative animation.

Envelope:

```
{ contract_version, run_id, generation, sequence, event_id,
  occurred_at, kind, payload }
```

Sequence is strictly increasing PER RUN and allocated transactionally with the associated authoritative state update. event_id is stable across replay (run_id + sequence is sufficient). Ordering uses sequence, never wall-clock timestamps. A complete snapshot replaces state at its through_sequence watermark; delta responses contain only events after the client watermark. These modes are mutually exclusive. Duplicate events are ignored by identity. Out-of-order or missing sequences trigger state refresh before further application. No silent omission of supported event kinds.

The frontend never merges domain entities across run IDs, generations or deck revisions. Prior runs remain separate visible history, including superseded findings. A changed deck shows results as belonging to the earlier revision and blocks deck-changing actions or steering against that old context; it cannot silently rebase them. Stop is permitted for that exact old-revision run. Existing server-side revision gates remain mandatory for all actions. Every stop, retry, steering or settings mutation carries expected_run_id, expected_generation and expected_revision. Compare run identity/generation atomically against the targeted current run. For stop, compare expected_revision to the TARGET RUN revision, not the current deck: users may stop old-revision work after editing the deck. Retry, steering and settings additionally compare against the CURRENT DECK revision. Return 409 plus current projection on mismatch without changing or billing another run. Stop on an already terminal matching run is an idempotent no-op; it never targets a replacement run. A deliberate request after a deck edit is a new submission, never steering of the old workspace. Capture the matching authority binding with the local mutation decision; external closure uses only that binding. Existing per-deck locks remain, but are not the sole correctness guard.

### Required event kinds

- run.accepted: accepted_at and queued state, plus steering origin and budget-group/deadline metadata where applicable.
- run.started: worker_started_at.
- activity.started / activity.finished: stable operation_id, approved public label key, category, timestamps, outcome completed/unavailable/failed. Repeated/parallel operations are valid; completion counts unique operation IDs, not polls. No planned denominator unless server declares one; v1 has no percentage.
- finding.upserted / finding.withdrawn: finding_id, version, text, type, source IDs, review state, applicability revision. Upsert replaces the SAME identity. Withdrawn findings remain visibly withdrawn within the bounded retained history; compaction is disclosed.
- answer.block.upserted: block_id, version, text, claim IDs, review state. Publish complete blocks only; no raw structured-output fragments. V1 may represent final content as ONE block and must not invent sentence-to-citation mappings. Changed blocks replace old versions visibly rather than duplicating them.
- claim.updated: claim_id, status supported/unverified/contradicted/withdrawn/superseded, evidence IDs, optional replacement ID. Status and factual coverage derive from existing review output, never from UI inference.
- steering.received / steering.applied / steering.rejected: steering_id, origin_run_id/generation, target_run_id/generation when created, effective obligations version or rejection code. Message/exclude/prioritize steering is supersede-and-restart, NEVER in-flight modification. On success, locally persist origin received then ended(superseded, superseded_by_run_id), target accepted(steered_from_run_id, steering_ids) and target steering.applied in one transaction. Applied means inclusion in the target frozen input, not answer fulfillment. A rejected instruction produces no replacement; rejection events only append to a still-active origin. Pin/unpin is presentation state, not a restart and not paid admission.
- stop.requested: records intention only; physical remote operation cancellation is not promised.
- run.ended: terminal lifecycle, ended_at, evidence_status, fulfillment, error if any. Terminal outcome and final artifact updates are persisted atomically.

No new domain updates after run.ended. Late provider responses may settle usage through existing accounting but cannot publish into terminal or replacement runs. A completed/stopped race is resolved by the authoritative transactional terminal transition, not by the browser's click time. Already-published findings are retained on stop; unfinished final prose is not promised. Recovery triggered by existing GET/claim paths terminalizes orphaned runs as interrupted. The client cannot infer interruption from silence. Accounting settlement is separate from terminal publication.

### Sources, review and early content

Citation fields: citation_id, claim_id, source_id, source_kind, title, relevant_excerpt, source_url nullable, source_version/date nullable, content_hash, truncation flag; tournament rate claims REQUIRE cohort window, denominator and event-size floor; suppress the rate if any is absent and disclose missing context separately. Missing fields are displayed as missing, never invented. External URLs are validated against safe protocols and rendered safely; quotes and model text are treated as untrusted content. No raw provider errors, internal prompts, credentials or private reasoning.

content_hash identifies captured canonical source text, with its source version; it does not claim currentness of a remote page.

Early publishable content must match a declared request obligation or subject AND meet a deterministic policy: grounded exact printed facts/rule excerpts with source identity, or explicitly UNRANKED retrieved candidates. Carry prerequisites, limitations, truncation and source freshness unknowns. Retrieval is not a strategic endorsement. Strategic recommendations remain behind existing semantic review gates. Unreviewed model prose is never published early. Final prose, when produced by the existing pipeline, remains visible with explicit block review limitations; this does not authorize actionable changes that failed existing review gates. Corrected text receives new version-bound claim identity and explicit replacement links; approval is never inherited onto edited text. The quality stream owns the publishability policy; transport cannot relax it.

### Durable journal, transport and boundedness

Add build_assistant_events in the existing SQLite database (owner/deck/run binding, sequence, event kind, payload); add jobs.last_sequence and immutable timestamps/terminal projection as additive fields. Domain mutations and event insertion share their existing transaction. Cover _begin, append, checkpoint, finish, stop/_cancel, settings supersession, steer, claim including expired-run sweeps, recover, invalidation and legacy upgrades. Do not infer missing events by comparing later snapshots. Copy required immutable rows under the lock, commit, then serialize outside the writer lock. Schema migrations are idempotent and versioned; no cross-store transaction is claimed.

Keep existing polling (1.8s initially) and authenticated session behavior. V1 is opt-in on the existing route; non-opt-in clients keep legacy fields. Missing v1 falls back to legacy. Unknown event kinds/major versions trigger snapshot or legacy fallback. Additive optional fields are ignored safely. Existing writer-lock behavior is measured before optimization.

One response has exactly one mode:
- snapshot: authoritative immutable entity pages at one watermark S. Client stages all pages then atomically replaces that run state at S, without applying accompanying deltas (there are none). It polls deltas after S afterward.
- delta: events in (after_sequence, through_sequence], maximum 100 events and 128 KiB including envelope. last_sequence is the available head captured for this response, not the applied watermark. Top-level run is captured at that same head and carries run.last_sequence; the client renders terminal labels only when its applied watermark equals run.last_sequence, so it cannot announce completion before final artifacts arrive. While paging a snapshot, top-level head is advisory until staged pages replace state and subsequent deltas catch up; no mixture of head and watermark entities is rendered. has_more follows through_sequence < last_sequence.
- reset_required: invalid, future, compacted or incompatible cursor; discard staged pages and request a new snapshot, never resubmit research.

Snapshots are frozen page bundles bound to owner/deck/run/generation/revision/watermark, with opaque authenticated tokens, 5-minute TTL and at most one active bundle per owner/deck/run; concurrent snapshot requests reuse an unexpired bundle with the same token/watermark if its watermark is at or above the compaction baseline, otherwise freeze a replacement. At most four active bundles / 32 MiB per owner; evict the oldest. Ordinary requests never invalidate another tab’s usable bundle. Use a bounded build_assistant_public_snapshots table in the same SQLite database, cleaned lazily on reads/writes and cascade-deleted with the session. No external cache. Expired/invalid pages reset; pages cannot mix watermarks. Each page is <=128 KiB and each bundle <=8 MiB/64 pages. Every page request rechecks access. Active writes do not change already-frozen pages. Client limits staged bytes to 8 MiB and discards superseded bundles.

Public entities: max 100 message/answer records, 24 active findings, 256 claim records, 256 citations, 256 activity operations, 100 steering records, and 128 retired finding summaries per run. Source excerpt <=8 KiB; text block/finding <=16 KiB; metadata <=4 KiB per entity. Retired finding summaries are <=2 KiB and steering text <=4 KiB. Total SERIALIZED public projection per run is <=7.5 MiB INCLUDING all entity metadata, relation IDs, run fields and JSON escaping, leaving page/envelope overhead within the 8-MiB bundle cap. Counts, individual byte limits and this aggregate limit are enforced before public publication; use the same explicit fallback/unavailable policy when any is exceeded. A valid projection must always be snapshotable. Larger complete final answers use ordered 16-KiB text blocks at deterministic boundaries, with a total <=1 MiB. These are transport segments, not new model reasoning steps. Each has answer_id, answer_version, logical_text_hash and segment_index/count; concatenate ordered segments exactly without inserting or dropping bytes. Claims bind to the LOGICAL answer artifact and its complete text, never the 16-KiB transport segments. No relevant prerequisite or claim is clipped to fit: use the existing bounded answer fallback or mark that artifact unavailable with an explicit oversize reason. Large legacy/raw experiment payloads remain in the existing authenticated detail views, with size/availability disclosures; they are not copied into the public projection. Missing detail routes are not invented; retain the legacy renderer for those artifacts until implemented. Numeric counters and entity ordering survive compaction.

Journal cap: 4096 events/run, 16384/deck and 8 MiB serialized journal/deck, never exceed the first applicable limit. Compact oldest events into a persisted projection baseline watermark in the same mutation transaction; old cursors reset to a snapshot. Events never individually exceed 32 KiB. Terminal run replay window is up to 24h subject to those caps and existing session retention. Cascade deletion and lazy TTL cleanup prevent unbounded snapshot/journal retention. Equivalence means baseline snapshot plus retained subsequent events equals the current bounded public projection, NOT unlimited historical transcript. Report compacted counts/history-unavailable labels. Baseline contains every retained entity and its review/version links.

Connection state is independent: on poll failure backoff 2/4/8/15s; visibility recovery refreshes state. Never resubmit on reconnect. No SSE/token streaming in this approval.

### Lifecycle and budget semantics

Allowed transitions: queued -> running or any terminal state; running -> any terminal state. Terminal states are completed, failed, interrupted, stopped, superseded; none transitions back. There is no persisted stopping state. Client stop_pending is request-local only. Every terminal path emits exactly one run.ended atomically with final local state; repeated identical terminalization is a no-op. First committed terminal transition wins; failures cannot overwrite an earlier completed/stopped/superseded run.

Mapping for newly instrumented runs, applied by the coordinator to finish() and every terminal writer:
- Explicit stop -> stopped; replacement/settings invalidation -> superseded with reason and replacement link when known.
- Runtime/provider/tool/budget failure -> failed with sanitized code, even if an explanatory message is persisted. A limit notice alone is not a substantive answer.
- Worker lease expiry/process recovery without an explicit runtime result -> interrupted.
- Normal final answer -> completed, independently of partial fulfillment/review. An unsettled provider checkpoint alone does NOT change it to interrupted; record provider_outcome_unknown as a separate accounting warning.
- Legacy ambiguous completed/interrupted rows retain stored lifecycle with legacy_outcome_uncertain=true; never rewrite history based on heuristics.

Retry is available for failed/interrupted/stopped/partial completed outcomes when current context and policy permit. It is a deliberate new request, subject to existing active-turn, queue and cost admission; eligibility is not a bypass. Nonretryable codes include authorization/context conflicts until resolved and exhausted allowance until reset. Transient unavailability is retryable later. No raw exception strings.

Preserve the existing shared authority turn for replacement steering: expose opaque budget_group_id (not usable as an authority credential), budget_started_at and absolute deadline_at. Replacement run gets a new run_id/generation but not a fresh financial cap, attempt/tool allowance or 180-second deadline. Predecessor in-flight usage counts against that same allowance; new work waits for physical permits. Reject steering if the shared turn is closed/expired; do not silently admit a new paid group. Timers show request-group elapsed primarily, with “restarted at …” boundary and optional attempt elapsed. A separate deliberate retry may request a new budget group through normal admission. Pin/unpin never affects it. Settings-driven supersession closes the old shared authority using the captured binding and permits no replacement admission until closure/reconciliation allows it; steering supersession explicitly preserves the shared authority. Each path records its closure policy, never infers it solely from lifecycle=superseded.

Stop atomically terminalizes the exact local run and captures its authority binding for closure; external authority closure follows existing fail-closed behavior. No new paid stage may pass admission after closure. Already-started calls may finish and be discarded; preserve physical worker permits until actual exit. background_work_pending is a best-known nullable operational observation, not proof of remote cancellation. Each response includes an operational section with nullable background_work_pending, cost_pending, provider_outcome_unknown and observed_at. It is unsequenced, recomputed, never journaled and excluded from replay equivalence. These observations may change after terminal publication without advancing last_sequence; clients refresh them independently of event deduplication. No new answer/domain events are allowed. Operational observations are the only persisted-run response information allowed to change after terminal publication (transport cursors/server time and access checks remain response metadata). Poll operational state every 5s while visible for at most 60s after terminal, then stop automatic polling, show cost pending as unknown and refresh on explicit request/visibility return; never poll indefinitely for unknown usage. Unknown usage remains reserved, never reported as zero. Admission/closure cross-store crash boundaries use the existing idempotent authority binding/deadline recovery; do not claim atomic billing+SQLite commits or exactly-once provider calls.

### Entity identity, obligations and legacy mapping

Snapshot entity collections are answer_blocks, findings (including bounded retired summaries), claims, citations, activity, steering and persisted obligations. Every record carries run_id and stable id; each event upserts or retires those exact records. Claims refer to the logical answer artifact (answer_id, answer_version, full text_hash), evidence_manifest_hash and span identity, with run-scoped IDs incorporating those values. Original review-pass IDs (c0, c1) are retained only as provenance. Review identity binds answer_id + answer_version + full logical text_hash + evidence_manifest_hash + exact logical span when available. Transport segment boundaries never enter review identity; span is null when no exact fragment mapping exists. A new text/evidence version cannot inherit a verdict. Correction creates a new claim with replaces and marks the old one superseded with replacement_id atomically. The replacement receives a verdict ONLY from its own matching receipt, otherwise unverified. corrected/no_supported_correction describe corrective-pass provenance, never per-claim verdicts. Blocks may remain a single final-content block where no exact fragment mapping exists; no guessed inline citations.

Only resolve relations within the run. Referenced entities accompany their first use in the same ordered transaction/bundle; unresolved or hash-mismatched references remain visibly unverified and trigger refresh, never supported. not_checked maps to unverified with review_method=not_checked. Status words supported/unverified/contradicted/withdrawn/superseded are retained only where actual receipts support them. An empty citation list never makes a claim reviewed.

Run evidence_status: not_started before any required review starts; reviewed only when ALL applicable published claims have matching text/evidence review receipts (even a contradicted verdict is a completed review, visibly shown); partial when some coverage or incomplete review exists; unavailable when no usable coverage exists at terminal, including zero claim mappings. Show supported/unverified/contradicted counts beside aggregate review status; reviewed does not mean correct. missing claims/coverage cannot be guessed from prose.

Persist obligations and their version with the frozen run input; planner may refine explicit task interpretation once without a new model call. Steering creates a new obligations version on the replacement. Final fulfillment maps complete->complete, partial->partial, nonanswer->partial plus missing_obligations=[answer] and legacy_fulfillment=nonanswer, unknown->unknown. pending maps to unknown before terminal and is forbidden at terminal; terminal pending becomes unknown with reason. Exact missing obligations remain separately listed. Contradictions do not become fulfillment approval.

Migration: legacy accepted_at/worker_started_at/ended_at/request IDs unavailable from immutable records remain null; never substitute mutable updated_at. Timing unavailable is valid. Legacy runs begin with a projection baseline at S=0; do not fabricate historic events or receipts. New writes use journaled semantics. Downgrade readers ignore additive fields; downgrade writers must disable v1 negotiation until upgraded because they cannot maintain the journal. Backout requires feature disable/drain before old code writes; no destructive downgrade migration. Runs touched by non-journaling writers are marked dirty by deployment/version metadata; on re-upgrade rebaseline them, invalidate outstanding cursors with reset_required, and synthesize no missing events. If dirty runs cannot be identified reliably, rebaseline all retained runs before enabling v1.

## 2. UX specification

One activity card at the end of the transcript while active: subtle pulse/static reduced-motion dot, latest confirmed label, elapsed m:ss, expandable actual operation history, separate Stop control. Preserve the composer for steering; label its busy action “Restart with this instruction” with helper text: “Restarts research using the remaining time and allowance; earlier work may still consume that allowance.” Distinguish received from incorporated. Keep superseded findings separated, with a visible restart boundary and original request timer.

Primary timer counts budget_started_at to the latest authoritative group/run endpoint and includes queue time and predecessor work; until group timestamps exist use accepted_at and label it attempt elapsed. Never present a restarted attempt as receiving a fresh 180 seconds. At terminal, freeze this run’s displayed elapsed using ended_at; later settlement does not change it. Queued explicitly says Queued; show active-work duration only if worker_started_at exists. Use server_time anchoring plus a monotonic local display tick; negative/invalid timestamps show timing unavailable. Tick is local and causes no network request. Reconnection reanchors. Freeze on terminal state. No ETA or percentage. Timer is outside ARIA live regions and can be hidden by collapsing activity.

Completed activity collapses into “Research finished · 1:24 elapsed · Show activity.” Separately show evidence review partial/unavailable and fulfillment incomplete. Stop acknowledgment says “Stop requested; the current operation may finish.” Confirmed stopped says “Stopped · published findings retained. An in-flight request may finish in the background and will be discarded.” Failed refresh says “Connection lost; research may still be running” with Reconnect. Never relabel transport loss as failed research. Use explicit terminal labels: Answer ready; Answer incomplete; No substantive answer; Failed; Interrupted; Stopped; Superseded. A generic “finished” receipt never hides missing obligations.

Preserve reading position, focus and disclosures; add Jump to latest when content arrives below the viewport. Replace default evidence JSON with readable source disclosures, retain raw data as secondary. Inline citation controls only where claim-to-source mappings exist. Copy and deliberate retry controls remain clear about new attempts. Enter sends / Shift+Enter newline on desktop with IME guard; explicit Send on touch. Draft remains until server acceptance.

One polite progress region announces meaningful stage/terminal changes, not each poll or second. Errors have one actionable alert. No repeated announcements of the transcript. Reduced-motion mode removes pulse and animated scrolling without hiding status. Preserve existing responsive drawer behavior; mobile redesign is outside approval scope.

## 3. Answer quality specification

Extend existing planner with answer obligations: task class, subject/deck revision, requested count, hard exclusions, soft preferences, required explanation dimensions and evidence requirements. No additional planner call solely for this schema. User constraints remain hard; model-inferred preferences are labeled as inferred.

Final fulfillment evaluates obligations separately from claim correctness: complete, partial with missing obligations, or unknown. Example “three repeatable draw creatures”: eligible distinct candidates, casting/activation costs, repeatability conditions, concrete deck interaction and comparative ordering, or explicit supported shortfall. Never invent a third card to satisfy count. Exact IDs, printed facts, totals and membership use deterministic verification where possible; strategic fit and comparative reasoning use existing semantic review.

Diagnose hand-authored retrieval plans vs model plans vs synthesis on a frozen task set. Strengthen expert strategy provenance using existing refresh/import workflow, while keeping printed rules, combo recipes, tournament observations and strategy interpretation separate. This spec approves design/measurement, not unrestricted third-party ingestion. No training, generic extra critique loop or Jev expansion. Stronger-model escalation is deferred until measured need, existing budget admission, and a separate bounded policy.

## 4. Speed specification

Instrument receipt, acceptance, queue, worker start, cost wait, provider permit wait/attempt, first grounded finding persisted, first rendered finding, final persistence and terminal rendering. Record task class, stage durations, attempts, tokens, cache hits and version hashes; omit conversation text. Browser observations are tagged client-observed and not trusted for billing or correctness. Report server and display latency separately; do not subtract unsynchronized clocks.

Publish deterministic grounded findings through the existing workspace before final synthesis. Preserve review gates for recommendations. Audit repeated semantic work before reusing judgments. A reusable judgment requires exact task scope, deck hash/revision, constraints/steering version, source/evidence hashes and freshness, prompt/schema/model/policy version, and owner/access scope. Missing validity input is a cache miss. Reuse cannot upgrade a subclaim into whole-answer approval. Same-ID replays do not create another admission; distinct deliberate attempts may incur charges. Cross-request in-flight coalescing is deferred; initial reuse is same-run exact verified evidence/judgments only. Steering replacement cannot assume a predecessor judgment finished; miss if no committed matching receipt exists.

Exact factual tasks may bypass strategic synthesis only when deterministic evidence fulfills all obligations; ambiguity routes to the normal path. Task-specific deadlines reserve final verification and persistence; retries only for transient errors within remaining time and cost allowance. Do not raise the global 180-second budget, remove verification, increase workers or add infrastructure to claim a speed win.

## 6. Acceptance and evidence

Contract fixtures cover duplicate submissions, conflicting IDs, duplicate/out-of-order events, cursor expiry, oversized delta, unknown version, refresh/reconnect, cross-owner access, changed revision, terminal/stop races, late provider results, process restart and steering receipt vs application. No repeat admission/charges from SAME-ID transport replay. Baseline plus retained events reconstructs the same bounded projection. Add concurrent stop/steer/finish/recovery, stale-tab stop, clock skew, terminal dedupe, steering under a nearly exhausted shared deadline, unknown-usage reservation, journal compaction and snapshot expiry tests. Inject crashes before/after external admission, local commit and authority closure; verify fail-closed reconciliation without another admission. GET maintenance may dispatch already-admitted work, never admit a new turn.

UX fixtures cover queued vs working, correct elapsed/frozen timer, no fake progress, evidence partial on completed answers, no silent screen-reader ticks, stable scroll/focus, reduced motion, retained drafts and distinct reconnect/retry semantics.

Quality frozen set spans card facts, rules, discovery, comparison, deck strategy, win conditions, follow-up constraints and insufficient evidence. Include Marchesa/Kinnan regressions and unfamiliar commanders. Independently score mechanical correctness, supported claims, eligibility/retrieval, prerequisites, request fulfillment and strategic usefulness. Heldout labels stay out of tuning. No fabricated cards/measurements, protected-cut violations or new critical rules errors.

Speed reports paired repeated runs by task class, cold/warm and single/concurrent, alongside cost per complete supported answer. Historical minute-long samples are motivation, not production percentiles. Targets to validate: healthy admission p95 <1s; first grounded local exact-fact finding within 5s; lower discovery/review completion latency with unchanged/lower cost and no quality regression. Percentiles require sufficient sample counts, reported explicitly. No numeric quality improvement claim before baseline. Early-content speed counts only findings relevant to the request obligations; an unrelated commander fact is not a success. Freeze baseline/candidate versions, scoring rubric and case labels before runs. Timeouts/nonanswers count as failed fulfillment and remain in latency/cost reports, never dropped. Release decision: zero new critical mechanical/protected-card errors; supported-claim accuracy and fulfillment nondecreasing on the frozen paired set; at least one intended metric improves with uncertainty reported and no cost increase per complete supported answer. If evidence is too small to support a decision, report inconclusive and do not claim a performance/quality win.
