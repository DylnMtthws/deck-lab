# Build workflow QA review — 2026-10-12

The review surface is **Build → open a deck → Goldfish simulator** on `https://qa.decklab.studio`. Production remains on its previously approved release.

## Review sequence

1. Import, build or generate a legal 100-card deck.
2. Run Goldfish. Each of the five scenarios uses 2,000 trials, with visible-hand mulligan decisions and the declared turn checkpoints.
3. Inspect coverage, observations and bounded traces. The Research Assistant answers questions about the current report in evidence mode. Its suggestions identify their tournament-list evidence and uncertainty.
4. Select at most three replacements, or edit up to three cards manually, then rerun. The run freezes the deck revision and compares it with previous experiments.
5. A changed deck also triggers independent-seed trials of both the frozen baseline and candidate. The report exposes values, denominators, intervals and reasons comparisons were suppressed.

## Generator

Commanders without an existing plan can use the Starter deck option within Build. It resolves real, legal cards from the catalog, prioritizes color-specific engines, requires a useful mix of roles, and holds lands to 36–40. Insufficient catalog depth produces an explanation. This remains a draft with an artifact-combat fallback, not a verified commander-specific competitive strategy. Generation, persistence, import and native simulation use the existing workflow.

## Native engine changes

Version 0.4.0 continues using the existing C++ simulator. Diagnostic-only support now includes Vivi's spell triggers, counters and once-per-turn mana; Curiosity/Ophidian Eye attachment and damage draws; Sauron's own Ring response; Call of the Ring; selected amass effects; more Grixis mana sources; current-resolution Oracle victories; and duplicate-aware Tainted Pact. A proven victory stops the game immediately. Positive samples include a witness and indexed game seed input.

Visible one-land opening hands can qualify with payable, visible two-mana acceleration. Neither the opening policy nor its bottoming decisions inspect hidden cards. The pilot remains a bounded heuristic.

`positive_finish_proof_rate` reports the lower bound of positively proven finishes across all trials. Unproved outcomes remain unknown. The old conditional finish rate stays unmeasured because the engine cannot establish all negative outcomes. Engine-event observations describe executed effects; a single token-production event does not prove a sustainable engine.

## Recommendations and comparisons

The assistant's current swap recommendations respond to missed-land-drop observations, use same-role tournament alternatives, preserve interaction slots, and require a known latest recorded candidate price no higher than the outgoing card. This is a price-increase guard, not a verified total budget. Theme remains a user review decision. Missing evidence produces search guidance instead of invented recommendations. Each applied replacement changes one physical copy, including when the outgoing entry is a basic-land stack.

Ownership, revision, fresh report, frozen lineage and the three-replacement cap are checked before applying proposals. Different settings, coverage or unsupported measurements suppress deltas. Held-out trials remain descriptive; no whole-deck superiority or multiplayer win-rate ranking is inferred.

## Operational and modeling limits

QA's infrastructure policy forbids external model API calls. The question interface uses current report evidence and explicit supported question categories. Live AI chat is not enabled; Jev also has no local credential configured. The TypeSafe design guidance was reviewed, but no confidence judgment is used as card-rules proof or mutation authorization.

Full card coverage, combat, arbitrary stack/combo resolution, comprehensive board-wipe replacement/protection rules, and commander-dependent hand classification remain unfinished. Partially implemented card text remains visibly unauthored in coverage. Sauron's opponent-cast triggers receive no invented opponents. The supplied primers still return JavaScript shells to the available reader, so fresh primer verification is not claimed.

## Validation evidence

Native full suite: 156 cases / 89,226 assertions passed. Native service boundary checks: 69 passed, including two version expectations updated to 0.4.0. Existing real-process integration and the 2,000-game legacy reproducibility digest: three tests passed.

Four complete supplied reference decks were exported from the existing read-only card corpus and each ran 2,000 trials per scenario locally in roughly 0.2–0.5 seconds. High-power Sauron produced 12 witnessed Oracle victories; other finishes remained unproved. These are authored-subset observations with substantial coverage limits.
