# Frozen coverage auditing and comparisons

Run `PYTHONPATH=src python scripts/audit_goldfish_coverage.py REPORT_DIR --oracle-dir ORACLE_DIR --output audit.json`. Reports use `<fixture-id>.json`; optional Oracle documents use `<fixture-id>-document.json`. The manifest fixes 100 playable slots per fixture and excludes the affordable Sauron sideboard. The audit verifies contiguous unique slots, declared totals, coverage counts and source SHA-256 hashes. It fails on contradictory input rather than inferring missing coverage.

`coverage-audit.native-0.4.3.json` is the frozen older baseline, not a claim about the current binary. Each deck records native card rows, exact executable-label and limitation counts, scenario measurement availability, bounded trace observations, an engine coverage gap queue and a separate pilot policy issue. Queue priority is categorical: absent definitions first, partial definitions second, intentionally inactive slots third. This order expresses investigation urgency; it is not a simulated importance score.

Oracle inventories contain nonempty text lines with every semantic mapping marked unverified. One line can contain multiple abilities or reminder text. Executable labels establish definitions, not execution; sampled turns cannot prove which individual abilities executed. No fully supported ability count or fixture pass verdict is inferred.

Optional `--evidence-dir DIR` manifests bind each fully supported card claim to the exact report hash, current source file hashes and passing positive plus negative/interaction test evidence file hashes. A manifest contains `report_sha256`, `sources: [{path, sha256}]`, and `claims: {"<slot>": {tests: [{kind, outcome, evidence_path, sha256}]}}`. Required kinds are `positive` and `negative_or_interaction`; outcome must be `passed`. A failed binding keeps the effective classification partial, records failures and causes the CLI to exit nonzero. These checks establish frozen evidence integrity and required regression categories; they do not independently certify every rule on a card.

Comparison preserves the existing schema, engine, settings and catalog identity checks. Legacy reports without dependency evidence still require identical global coverage. New native opening reports provide `comparison_coverage` with version 1, scope `native_opening_policy`, algorithm `opening-policy-dependencies.v2`, `dependency_accounting_complete`, and a dependency fingerprint. The app recognizes only the three native opening measurements: qualified opening rate, mean mulligans and mean kept cards. Other scenarios retain global coverage equality.

This scope describes the fixed partial visible-hand policy. It does not establish real opening success or an optimal strategy pilot. Unchanged unknown card identities and quantities remain in the dependency fingerprint. Costs and source colors are intended deck variables; missing face inputs, source/payment gate kinds and parameters, source quantities, action eligibility, modifier gates and ritual capabilities remain modeling dependencies. Exact basic land names are omitted, permitting a basic land color change without implying a modeling change. Post-cast damage, draw quantity and engine triggers do not execute during this assessment or affect its current profile ranking, so they are excluded. Commander profile ranking additionally reads author eligibility and real costed mana activation inputs/outputs; its fingerprint binds those fields and commander profile flags. Unknown Oracle identity and source-text hashes are retained. Table context is included in the settings fingerprint because opponent/color context and life floors affect source payment.

Malformed, unknown-version, unknown-scope or mismatched evidence suppresses the metric delta. A change in unrelated global coverage can retain only opening deltas whose dependency evidence agrees. Every retained delta remains descriptive within the fixed partial policy; no winner or performance improvement is inferred.
